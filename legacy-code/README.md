# Legacy Code ยังไงดี

### "โค้ดนี้ใครเขียนวะ"

ทุกคนเคยพูดประโยคนี้ครับ (บางทีก็ตัวเองเขียนเมื่อปีที่แล้ว)

Legacy code ไม่ได้แปลว่า "โค้ดไม่ดี" นะครับ มันแปลว่า **โค้ดที่ยังทำงานอยู่ ทำเงินให้บริษัทอยู่ แต่ไม่มีใครกล้าแก้** เพราะ:

* ไม่มี test
* ไม่มี documentation
* คนเขียนลาออกไปแล้ว
* แก้ตรงนี้พังตรงโน้น
* business logic ฝังอยู่ในที่ที่คาดไม่ถึง

### กฎข้อเดียวที่ต้องจำ

> **"ทำให้มันดีขึ้นทีละนิด ทุกครั้งที่แตะมัน"**

ไม่ต้อง refactor ทั้ง project พรุ่งนี้ แค่ทุกครั้งที่เปิดไฟล์มาแก้ bug หรือเพิ่ม feature ทำให้มันสะอาดขึ้นนิดนึงก่อนออก — **Boy Scout Rule**

### บทความในหมวดนี้

| บทความ | เนื้อหา |

| [**Refactoring ทีละขั้น**](refactoring-guide.md) | ขั้นตอน refactor legacy code อย่างปลอดภัย ไม่ต้อง rewrite ทั้งหมด |

### สิ่งที่อย่าทำ

* ❌ อย่า rewrite ทั้ง project จากศูนย์ — 90% ไม่เสร็จ
* ❌ อย่า refactor โดยไม่มี test — จะพังโดยไม่รู้ตัว
* ❌ อย่าดูถูกโค้ดเก่า — มันทำเงินให้บริษัทมาจนถึงวันนี้

จำไว้ครับ legacy code ไม่ใช่ศัตรู มันคือ code ที่ **ประสบความสำเร็จมาแล้ว** แค่ต้องการคนดูแลที่เข้าใจมัน

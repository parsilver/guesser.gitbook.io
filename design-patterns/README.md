# Design Patterns

### Design Pattern คืออะไร

พูดง่ายๆ มันคือ **วิธีแก้ปัญหาสำเร็จรูป** ที่คนเก่งๆ เขาคิดไว้ให้แล้ว

เคยเขียนโค้ดแล้วรู้สึกไหมครับว่า "ปัญหานี้คนอื่นต้องเคยเจอมาก่อนแน่ๆ" — ใช่ครับ เขาเจอมาแล้ว แล้วเขาก็คิดวิธีแก้ไว้ให้แล้วด้วย นั่นแหละ Design Pattern

### ทำไมต้องรู้

ไม่ใช่เพราะสอบถาม interview ครับ (ก็จริงอยู่นะ แต่ไม่ใช่เหตุผลหลัก)

เหตุผลจริงๆ คือ:

* **แก้ปัญหาเดิมซ้ำๆ ได้เร็วขึ้น** — ไม่ต้องคิดใหม่ทุกครั้ง
* **คุยกับคนอื่นรู้เรื่อง** — พอบอก "ใช้ Strategy Pattern" ทีมก็เข้าใจทันที
* **โค้ดยืดหยุ่นขึ้น** — เพิ่ม feature ใหม่โดยไม่ต้องไปแก้โค้ดเดิม
* **อ่าน source code framework ได้** — Laravel, Symfony ใช้ pattern พวกนี้เต็มไปหมด

### Pattern ที่ครอบคลุมในบล็อกนี้

เลือกมาเฉพาะตัวที่ **ใช้บ่อยจริง** ในงาน PHP ครับ ไม่ได้เอามาทั้ง 23 ตัวจาก GoF

| Pattern | เหมาะกับปัญหา |
|---------|--------------|
| **Strategy** | อยากเปลี่ยน algorithm/logic ได้โดยไม่ต้องแก้ class หลัก |
| **Observer** | อยากให้หลายส่วนตอบสนองต่อ event เดียวกัน |
| **Decorator** | อยากเพิ่ม behavior ให้ object โดยไม่แก้ class เดิม |
| **Factory** | อยากสร้าง object ที่มีหลาย type โดยไม่ต้อง if-else ยาว |

แต่ละตัวอธิบายด้วยโค้ด PHP ตรงๆ ครับ ไม่ใช่ทฤษฎีลอยๆ — เอาไปใช้ในโปรเจกต์ได้เลย
